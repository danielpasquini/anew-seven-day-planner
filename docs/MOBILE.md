# Anew for iOS and Android

The mobile application lives in `native/` and uses genuine React Native screens with Expo SDK 57 and Expo Router. The earlier Capacitor/Vite projects have been retired. Next.js still serves the web app. Both share the local guide builder, English content, resources, legal version and backup validation.

## Quick testing

From the repository root:

```sh
npm ci
npm run native
```

Or run the requested command in the mobile directory:

```sh
cd native
npx expo start --go
```

Use a compatible Expo Go version on the phone, keep it on the computer's network and scan the terminal QR code. Press `w` for React Native Web. An occupied port can be changed with `--port 8082`; the current session uses that port.

Choose **I already have an account**, then **Fill test login**, or enter:

| Field | Public example value |
| --- | --- |
| Email | `tester@anew.local` |
| Password | `AnewPreview2026!` |

This opens a complete memory-only demo, without creating a Firebase user or accessing another user's records. The reserved address cannot reach real signup, recovery or sign-in SDK calls. Incorrect credentials do not open it. The three-section read-only guest preview remains available separately.

Test access requires `EXPO_PUBLIC_ENABLE_DEMO=true`. The ignored local mobile environment enables it; `.env.example` defaults false. EAS development/preview profiles enable sample access, while production explicitly disables it. Web separately requires `NEXT_PUBLIC_ENABLE_DEMO=true`. Neither flag authorizes a server request.

Expo Go is a shared testing host, not a released Anew app. Real account services are disabled there. Guides, notes, activities and favorites stay in memory; restarting discards them. Only non-sensitive opening/journey-seen preferences use AsyncStorage. Use sample information. Exported files remain wherever the user saves them.

## Native experience

The native interface includes ten optional questions, a locally prepared eight-section guide, English resources, editable weeks/schedules, history, settings, legal documents and backups. The first leaf/branch opening lasts about 9.2 seconds; returning openings last about 1.4 seconds. Skip and reduced motion are supported.

Original quiet `zen.wav` and `tap.wav` tones are generated by `scripts/generate-native-sounds.cjs`. Sound is opt-in and stops on mute, skipped opening and backgrounding. Pending seeks cannot restart canceled playback. No microphone or background-playback permission is requested. Device audibility and interruptions still require testing. [Expo Audio](https://docs.expo.dev/versions/v57.0.0/sdk/audio/).

Artwork comes from `public/anew-icon.svg`. Run `node scripts/generate-native-art.cjs` to regenerate web and Expo PNGs. The iOS icon is opaque 1024×1024. Expo creates operating-system launch screens from app config; the longer in-app animation is separate.

## Installed builds and Firebase later

The provisional iOS bundle ID and Android package are `com.retomada.app`; the displayed name is Anew. Confirm identifiers before registration. The owner deferred cloud setup for existing project `anew-58b4a`. No Firebase platform app has been registered by this work.

Configured installed builds have prepared Firebase JS Email/Password, recovery, verification and four acknowledgements. Firebase refresh credentials and Firestore cache stay in memory. Local journals use UID-scoped AsyncStorage and are never uploaded to Firestore; only acknowledgements use the database. Reopening an installed build requires signing in again. Persistent automatic login is not claimed. [Expo Firebase guidance](https://docs.expo.dev/guides/using-firebase/).

Only public `EXPO_PUBLIC_FIREBASE_*` values belong in the mobile environment. There is no Gemini credential or Gemini endpoint in the native app. Native AI is unavailable; the first guide uses local rules.

EAS profiles are prepared. Signing, an Expo project/account and store records remain operator tasks. From `native/`, a development build can be requested with `npx eas-cli@latest build --profile development --platform android`; iOS requires appropriate Apple credentials. No EAS build/submission was performed. Generated `native/android/` and `native/ios/` are ignored; configure native behavior through app config/plugins. [Expo continuous native generation](https://docs.expo.dev/workflow/continuous-native-generation/).

## Backups and storage

Export uses a temporary cache file and the system share sheet, then attempts cleanup. Import uses a document picker with size, lifecycle, owner and full-schema validation. Sharing completion does not prove the file was saved.

Android sets `allowBackup=false`. `plugins/with-backup-policy.cjs` generates legacy and Android 12+ exclusions for app cloud backup and device transfer. Custom-build settings cannot change Expo Go's container. [Android backup rules](https://developer.android.com/identity/data/autobackup).

Android prebuild succeeded. Generated manifest references both rule files, and XML parsing validated all nine excluded storage domains for legacy backup, cloud backup and device transfer. The generated manifest also removes microphone, legacy external-storage and overlay permissions; an actual merged APK manifest has not been built. Expo SystemUI is installed for the configured appearance.

Installed AsyncStorage 2.2.0 excludes its iOS storage directory from backup by default. App config explicitly sets `RCTAsyncStorageExcludeFromBackup=true`. This replaces the retired WebKit policy; no WebKit location is assumed. An exclusion setting is not backup/restore test evidence. [AsyncStorage backup guidance](https://react-native-async-storage.github.io/async-storage/docs/advanced/backup/).

Before release, inspect actual journal storage/exclusion after saves and upgrades; test logout/restart, deletion/export and physical iCloud/computer backup-and-restore using synthetic entries. Test Android backup/device transfer and generated XML/manifest. Device access, encryption and user-exported files are separate. Anew does not add journal encryption or an app lock.
