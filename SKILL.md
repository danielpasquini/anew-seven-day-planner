# Anew App

Read [AGENTS.md](AGENTS.md) before working in this repository and [native/AGENTS.md](native/AGENTS.md) before changing the native app. Use [README.md](README.md) for the product and service boundaries, and the installed Next.js guides before writing Next.js code. Resolve conflicting historical review notes against current instructions and source files.

Preserve the English default, optional personalization/spirituality/AI, public preview, isolated demo, and UID-scoped records. For Firebase work, read the applicable official Firebase skills, inspect existing resources, and use the existing `anew-58b4a` project.

Use a Weeks-only product flow. New Weeks inherit the previous Week's setup, selected preferences, optional sections, activities when the pattern stays the same, and daily text; completed checkboxes start unchecked. Copies must be independent, and existing records must remain unchanged. Legacy guide/template storage is compatibility data, never a separate creation or navigation step. Keep personalization, psychology preferences, spirituality, and Gemini optional. Each preference group supports a selectable Other option and a free-text example.

## Definition of done

Record the revision or diff, date, commands, exit codes, test counts, source paths/lines, URLs, and screenshots used as evidence. Never include secrets or personal notes in evidence; use disposable fixtures. Historical QA reports and source inspection do not establish a current rendered or live-service pass.

### Verification gate and report

- Run every check in a first pass before showing a completed result. Record failures and unavailable evidence separately; unavailable evidence cannot receive PASS.
- If more than two checks fail on the first pass, stop before patching the output. Report the failed checks and the evidenced process cause (for example, a missing prerequisite, conflicting reference, or omitted verification step). If the cause is unknown, say so. Missing evidence counts as a failed check for this gate; do not split or merge checks to avoid it.
- If at most two checks fail, fix the failed requirements within the authorized task, then run every check again before presenting the result. Also run the complete checklist a second time when the first pass has no failures. Do not treat elapsed time or an unavailable external service as a fix. Preserve the first-pass evidence and report any remaining failure.
- Give one line per numbered check: `PASS — <check>: <current evidence>` or `FAIL — <check>: <evidence or missing evidence and reason>`. State the tested scope and attach accessible logs/screenshots or exact source/test references. List all unverified observations and why they could not be verified, even when another part of that check passed. Do not claim the job is done while a required check remains unverified or failed.
- Keep progress updates separate from the completion report. Follow the integrated review after every five coherent changes required by AGENTS.md, and inspect each change individually before the next batch.
